# 编辑器架构升级评估

日期：2026-08-01

## 背景

当前编辑器基于 CodeMirror 5，通过 `markText()`、`setBookmark()`、
`addLineWidget()` 和行样式实现 Markdown 预渲染，并包含图片、表格、代码块、
Mermaid、标题折叠、查找高亮和斜杠菜单等交互。

现有装饰系统在光标进入需要显示源码的区域时，会清除并重建一个较大的装饰范围。
虽然可以通过跳过无变化更新、保持滚动锚点和限制空白区域点击来减轻闪烁，但只要确实需要
更新，变化区域上方未变化的内容仍可能被重复创建。

## 理想架构

抛开现有实现，长期最合理的方案是：

> CodeMirror 6 + Lezer 增量语法树 + 声明式 DecorationSet + 稳定块组件 +
> 视觉滚动锚点。

一次编辑应经过以下流程：

```text
用户操作
  ↓
编辑事务
  ↓
增量更新语法树
  ↓
定位受影响的语法节点
  ↓
映射未变化节点及装饰的位置
  ↓
只重建发生变化的装饰或块组件
  ↓
浏览器局部更新 DOM
```

普通输入、点击、获得焦点、选择变化和滚动不应触发全局渲染。只有解析器配置、全局字体、
页面宽度、主题或文档整体替换等全局状态变化，才应允许重建整个可视区。

## 核心设计

### 增量语法树

使用 Lezer 维护 Markdown 语法树。修改某一行时，只重新解析受影响的语法节点，例如完整
表格、列表或围栏代码块；其他节点保持身份，只映射到新的文档位置。

### 分层装饰

装饰拆分为相互独立的三层：

1. 行内层：粗体、斜体、链接、高亮和行内代码。
2. 行结构层：标题、列表、引用和任务项。
3. 块组件层：表格、图片、代码块和 Mermaid。

修改一个行内格式时，不应影响其他行，更不应重新创建 Mermaid 等重量级组件。

### 稳定块组件

每个块组件使用稳定节点标识和内容哈希：

```javascript
{
  id,
  type: 'mermaid',
  sourceHash,
  theme,
  renderedSvg,
  measuredSize
}
```

源码和主题没有变化时复用组件结果。节点只发生位置移动时，仅更新位置映射，不重新生成
SVG 或 DOM。

### 滚动稳定

高度变化时，以变化区域上方最近的稳定语法节点作为视觉锚点：

```text
新 scrollTop = 旧 scrollTop + 锚点新位置 - 锚点旧位置
```

变化区域在视口下方时不调整滚动；变化区域上方未变化的内容不参与重绘。

### 异步 Mermaid

Mermaid 渲染任务必须携带节点版本和内容哈希。任务完成时重新校验节点版本，过期结果直接
丢弃；缓存命中时复用 SVG，避免重复渲染和高度抖动。

## 升级成本

这不是 CodeMirror 依赖版本的机械替换，而是编辑器内核重构。CodeMirror 5 的
`markText()`、`setBookmark()`、`addLineWidget()`、`addLineClass()`、`operation()`、
`getCursor()` 和 `replaceRange()` 等 API 在 CodeMirror 6 中没有直接兼容形式。

结合当前功能量，单人开发达到基本功能等价，预计需要 **4～8 周**；如果要求视觉、交互、
中文输入、滚动和所有边界行为与当前版本一致，预计需要 **6～10 周**。

| 改造部分 | 主要工作 | 成本 |
|---|---|---:|
| 编辑器基础层 | 文档、选区、事务、撤销以及双编辑器实例 | 中 |
| Markdown 渲染 | Lezer 语法树、源码显隐和分层装饰 | 高 |
| 块级组件 | Mermaid、表格、图片和代码块 | 很高 |
| 键盘操作 | 列表、Tab、回车、退格和斜杠菜单 | 高 |
| 光标与选区 | 中文输入、光标高度和跨行选区 | 高 |
| 滚动系统 | 视觉锚点、异步高度变化和双栏滚动 | 高 |
| 查找与高亮 | 搜索结果、当前命中和选区装饰 | 中 |
| 剪贴板 | HTML、文本、图片和文件粘贴 | 中 |
| 测试与兼容 | Electron、输入法、性能及行为回归 | 很高 |

## 主要风险

### 功能回归

现有标题、列表、表格、图片、代码块、Mermaid、链接、查找、折叠和斜杠菜单均依赖当前
编辑器行为。迁移时任何一项都可能出现选区、撤销、焦点或保存行为差异。

### 中文输入法

需要在真实 Electron 环境中验证拼音组合输入、候选词选择、全角标点、选区替换和撤销。
单元测试无法完全覆盖输入法行为。

### CSS 和布局

CodeMirror 6 使用 `.cm-editor`、`.cm-scroller`、`.cm-content` 和 `.cm-line` 等新 DOM
结构。当前阅读字体、禅模式、光标、选区和页面宽度样式需要重新适配。

### 双轨期间的维护成本

为了可回滚，新旧编辑器需要并存一段时间。这会暂时增加代码量，并要求同一功能同时验证
两个实现。

## 推荐迁移路线

不建议一次性替换。推荐通过配置开关并行建设新内核：

1. 将 Markdown 结构解析、键盘规则和格式操作继续提取为纯函数。
2. 建立 CodeMirror 6 编辑器适配层，实现文档、选区、输入、保存和撤销。
3. 迁移普通 Markdown、标题、列表、引用和行内格式。
4. 迁移图片、代码块、表格和 Mermaid 块组件。
5. 迁移查找、折叠、斜杠菜单、剪贴板和双栏编辑。
6. 在真实 Electron 环境中完成中文输入法、滚动和性能验证。
7. 通过配置开关逐步扩大新内核使用范围。
8. 达到功能和性能标准后删除旧内核。

每一阶段都应保留旧编辑器作为回退路径，避免重构期间应用长期不可用。

## 当前阶段的建议

如果近期目标主要是解决点击闪烁和无效重绘，立即升级 CodeMirror 6 的投入过高。当前更
合理的方案是在 CodeMirror 5 上实现：

- 行级与块级脏区增量装饰；
- 变化范围合并和结构边界扩展；
- 未变化装饰及重量级组件复用；
- Mermaid 内容哈希缓存；
- 变化区域上方稳定节点滚动锚定；
- 全量渲染作为主题、宽度及异常恢复的后备路径。

该方案预计约为完整架构迁移成本的 **20%～30%**，可以明显减少闪烁和无效 Mermaid
重绘，同时为未来迁移积累清晰的结构边界和纯函数模块。

## 结论

长期架构应选择 CodeMirror 6、Lezer 增量语法树和声明式增量装饰；但以当前需求和项目
规模衡量，短期应优先完善 CodeMirror 5 的脏区增量渲染。只有在计划持续增加块级编辑、
大型笔记、插件系统、协同编辑或更多交互式组件时，完整内核升级的收益才足以覆盖其成本。
