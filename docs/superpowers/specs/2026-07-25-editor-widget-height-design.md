# 编辑器预渲染高度同步修复设计

## 问题

普通单栏编辑器会把 Markdown 图片和围栏代码块替换为可视化部件。图片加载以及代码块
挂载后，替换节点的实际高度可能发生变化，但 CodeMirror 没有收到高度失效通知，内部
保存的行高和页面实际布局因此不一致。用户点击预渲染内容下方时，光标命中位置会偏移，
编辑区滚动条也可能跳动。

## 方案

使用 CodeMirror 装饰对象提供的局部高度失效能力：

- 图片部件对应的图片加载或加载失败后，调用该图片 `TextMarker` 或 `LineWidget` 的
  `changed()`。
- 代码块替换标记挂载后，在下一帧调用其 `TextMarker.changed()`，确保浏览器完成布局
  后 CodeMirror 重新测量高度。
- 回调执行前检查装饰对象仍然有效，避免装饰已被清除时产生异常。
- 不调用全局 `CodeMirror.refresh()`，避免无关行重新测量和额外滚动扰动。
- 左右编辑器共用同一套装饰渲染逻辑，因此修复应用于公共实现，但回归场景以普通单栏
  主编辑器为准。

## 边界

本次仅修复图片和围栏代码块的高度同步，不改变预渲染样式、点击选中方式、代码编辑方式
或滚动定位策略。表格等尺寸同步且已有明确交互的部件不在本次范围内。

## 测试

增加自动化回归测试，验证：

1. 图片 `load` 和 `error` 事件会使对应 CodeMirror 装饰高度失效。
2. 代码块挂载后的下一帧会使对应替换标记高度失效。
3. 实现使用局部 `changed()`，不会以全局 `refresh()` 代替。

完成后运行相关测试、完整 `npm test`、`node --check renderer.js` 和
`git diff --check`。
